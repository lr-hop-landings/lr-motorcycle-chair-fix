## Проверки

- HTTP 200 для каждого из пяти адресов, без промежуточных перенаправлений.
- Уникальные canonical URL, один H1 и 13 секций на каждой странице.
- Все 20 направленных взаимных ссылок присутствуют. Главная ведёт на четыре типа техники; каждая страница техники ведёт на главную и три соседних раздела.
- Якорные ссылки находят существующие ID. Текущий раздел отмечен без ссылки на самого себя.
- В каждом квизе правильный `data-page-path`; на дочерних страницах правильный `data-vehicle` и три вопроса, на главной четыре. Путь в скрытом поле обратного звонка также проверен в серверном HTML.
- Все изображения в итоговом HTML локальные, файлы существуют: 32 элемента img на главной, по 23 на дочерних страницах. Главная содержит восемь кейсов, страницы техники — по пять.
- Сохранённые новые страницы повторно открыты в Gutenberg: нет предупреждений о повреждённых блоках; кнопка сохранения неактивна. В проверенных редакторах нет ошибок console error.
- В браузере пройдена цепочка главная → мотоциклы → скутеры → квадроциклы → багги → главная.
- Просмотрены первые экраны четырёх страниц техники в обычном окне Chrome и при размере 390×844. Горизонтального переполнения нет на всех пяти страницах (375 px полезной ширины с полосой прокрутки).
- На мобильной странице багги пройдены три вопроса до результата: техника не спрашивается повторно, в результате указано «Багги». Выбор сначала подсвечивается, затем вопрос плавно меняется. Персональные данные не вводились, заявки не отправлялись.

Для WP-CLI использовались PHP и конфигурация Local, путь к тестовому WP передавался явно. Проверка HTTP требует доступа к локальной сети: первый запуск в сетевой песочнице был заблокирован; повтор с разрешённым локальным доступом прошёл, `failures: []`. Несвязанное предупреждение Local об отсутствующем `php_imagick.dll` оставлено без изменения.

Это проверка переноса, сохранения, связей и основных состояний, не заявление о попиксельной идентичности каждого возможного состояния. Обработчик отправки заявок по-прежнему не подключён.

## Повторное использование

`examples/catalog.json` содержит пять JSON-манифестов и согласованные адреса. Панель «Импорт страницы» предлагает их в поле «Готовая страница».

`ops/prepare-pages.php` предназначен только для этого локального WP: предварительная проверка конфликтов, создание черновиков, затем публикация после проверки контента и взаимных ссылок. `ops/verify-pages.php` — повторяемый read-only аудит. Эти служебные скрипты не входят в устанавливаемый ZIP плагина.
