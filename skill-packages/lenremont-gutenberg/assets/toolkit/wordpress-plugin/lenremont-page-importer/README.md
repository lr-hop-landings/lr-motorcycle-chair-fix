## 0.8.0: SEO при импорте

JSON может содержать `seo`: `title`, `description`, `breadcrumbsTitle`, `ogTitle`, `ogDescription`; необязательно `canonical`, `breadcrumbsUrl`, `ogImageId` (ID из медиатеки текущего сайта). Все пять примеров содержат индивидуальные тексты SEO.

Интеграция предназначена для существующих полей `on_yoast_wpseo_*` в метабоксе сайта lenremont.ru. Это не универсальная интеграция со стандартной панелью Yoast на любом сайте. Значения заполняются в видимых полях, отправляются штатным механизмом метабоксов при нажатии «Сохранить» и обрабатываются существующим серверным обработчиком сайта. Плагин не создаёт второй обработчик, не пишет напрямую в таблицы Yoast и не добавляет дублирующие метатеги.

- «Заполнять SEO из JSON» включено по умолчанию при импорте блоков.
- Для существующей страницы загрузите её JSON и нажмите «Применить только SEO»: содержимое, заголовок страницы и URL не меняются.
- Заполненные поля сохраняются, если не включена опция «Перезаписывать заполненные SEO-поля». Пустые и отсутствующие значения JSON ничего не удаляют.
- «Отменить последнее заполнение SEO» возвращает предыдущие значения, не затирая последующие ручные правки. Отмена блоков Gutenberg не отменяет значения метабокса.
- Если поля отсутствуют/недоступны, панель явно сообщит об этом. Значения не считаются сохранёнными до сохранения страницы.
- Canonical и URL хлебных крошек принимают полный http(s) адрес или путь от корня текущего сайта. В примерах они намеренно не заданы: сохраняется стандартное поведение сайта. Индексация, robots и редиректы не меняются. Картинка OG требует отдельного выбора в медиатеке; ID нельзя переносить между сайтами.

Пример SEO-only JSON: `{"seo":{"title":"Перетяжка сидений багги в СПб | Ленремонт","description":"Описание услуги для поиска","breadcrumbsTitle":"Перетяжка сидений багги"}}`. Для кнопки «Преобразовать в блоки» по-прежнему нужен полный манифест с `sections`.

## Исправление 0.7.2: классические темы и редактор

- Устраняется добавляемая WordPress обёртка групп только внутри `lr-reference` при выводе. Сохранённый контент не изменяется; обычные группы вне лендинга не затрагиваются.
- Редактор включает современную структуру групп для документа из одного корневого `lr-reference` и снимает стандартное ограничение ширины вложенных блоков. При удалении лендинга исходная настройка редактора восстанавливается.

Плагин добавляет в редактор Gutenberg боковую панель «Импорт страницы». Она принимает:

- семантический HTML;
- готовую разметку Gutenberg.

Преобразование выполняется в браузере редактора. Результат становится обычным деревом блоков и записывается WordPress только после нажатия «Сохранить».

## Базовый формат манифеста (v1)

```json
{
  "version": 1,
  "title": "Название страницы",
  "theme": "motorcycle",
  "sections": [
    {
      "type": "hero",
      "title": "Заголовок",
      "text": "Вводный текст",
      "image": { "src": "https://example.test/image.webp", "alt": "Описание" }
    }
  ]
}
```

Поддерживаемые типы секций: `hero`, `proof`, `links`, `cards`, `services`, `materials`, `pricing`, `process`, `portfolio`, `faq`, `contact`, `content`.

Поддерживаемые вложенные блоки: `heading`, `paragraph`, `image`, `buttons`, `list`, `separator`, `spacer`, `quote`, `details`, `cards`, `columns`, `quiz`, `beforeAfter`, `leadForm`.

## Точный перенос пяти лендингов — 0.6.1

В поле «Готовая страница» выберите главный лендинг, мотоциклы, скутеры, квадроциклы или багги. Нажмите «Загрузить пример» → «Проверить» → «Преобразовать в блоки». Если страница уже заполнена, появится подтверждение замены. Затем отдельно сохраните страницу. Каждый пример содержит 13 секций; каталог находится в `examples/catalog.json`.

На тестовом WordPress используются следующие уникальные адреса:

| Страница | ID | URL |
| --- | --- | --- |
| Главная | 11 | `/peretyazhka-sidenij-mototransporta/` |
| Мотоциклы | 19 | `/peretyazhka-sidenij-mototransporta-motocikly/` |
| Скутеры | 20 | `/peretyazhka-sidenij-mototransporta-skutery/` |
| Квадроциклы | 21 | `/peretyazhka-sidenij-mototransporta-kvadrocikly/` |
| Багги | 22 | `/peretyazhka-sidenij-mototransporta-baggi/` |

Главная связана с четырьмя страницами техники. На каждой странице техники есть ссылка «Все виды техники» на главную, ссылки на три соседних раздела и отметка текущего раздела. Ссылки относительные, в пределах сайта. Предыдущие адреса всех пяти страниц сохранены как точные правила 301-перенаправления сразу на конечный URL, без цепочки. Корневая страница сайта и глобальные настройки темы не менялись.

Для тестовой блочной темы выберите шаблон страницы **«Ленремонт — полный лендинг»**: он убирает дополнительную шапку, заголовок и подвал темы. На тестовой странице ID 11 этот шаблон уже выбран. Обычные страницы и шаблоны темы не изменяются. В классической теме потребуется проверить её собственный полноширинный шаблон.

Все пять примеров используют **JSON v2, профиль `astro-main-v1`**. Они автоматически собираются из соответствующих HTML-файлов `dist/`, а не пересказывают страницы через типовые секции. В репозитории исходного лендинга:

```sh
npm run build
node wordpress-plugin/export-reference.mjs
```

Получается 468 блоков на главной и по 418 на страницах техники (с учётом вложенных):

- `core/group`, `core/heading`, `core/paragraph` для контейнеров и основного текста;
- `lenremont/element` для ссылок-карточек, списков, FAQ и других семантических элементов;
- `lenremont/text` для редактируемых подписей, `lenremont/picture` для изображений с заменой из медиатеки;
- `lenremont/art` для доверенных SVG;
- отдельные блоки исходного квиза и служебных окон / мобильной панели.

Весь лендинг не помещается в один HTML-блок. Секции можно переставлять через список блоков. Основные тексты, ссылки и изображения редактируются в Gutenberg. SVG, логика квиза и содержимое служебных окон пока управляются кодом профиля; в редакторе у них есть отдельные блоки, но не полноценные конструкторы настроек.

Вместе с JSON плагин поставляет исходные стили, шрифты, изображения и проверенные скрипты. Работают исходная карусель, восемь сравнений «до/после» на главной и по пять на страницах техники, ветвление квиза, FAQ, окна связи и мобильная панель. На страницах техники тип уже выбран, поэтому квиз содержит три вопроса вместо четырёх. Сохранены индивидуальные цвета, тексты, изображения и служебные поля форм каждой страницы. Шрифт изолирован под именем `LR Reference Manrope`, чтобы стили WordPress не подменяли его начертания.

Произвольные скрипты из входящего JSON не выполняются. SVG и окна выбираются только по ключам из поставляемого набора. HTML-теги, атрибуты, ссылки и inline-стили проходят белые списки.

Сохранены исправления 0.3.0:

- Нативный `DOMParser` больше не удаляет текст при очистке inline-разметки.
- Заголовки, абзацы и кнопки сохраняются после повторного открытия редактора.
- Вложенные контейнеры не сжимаются до ширины текста темы; адаптивные сетки и Manrope применяются также в редакторе.
- Главный пример включает четыре шага квиза с исходными ветками и рекомендациями, QR-коды мессенджеров и фотографии.
- Кнопки создаются внутри `core/buttons`; секции имеют понятные имена для списка блоков.

Проверки:

```sh
node tests/converter.test.cjs
node tests/validate-manifest.mjs
wp eval-file tests/wp-smoke.php --user=admin
```

`tests/browser-regression.html` запускается через локальный сайт и проверяет конвертер с настоящим браузерным `DOMParser`, включая сохранность 111 нативных текстовых блоков примера. Ожидаемый результат: 16 проверок без ошибок. Дополнительно повторное открытие сохранённой страницы проверяется в настоящем Gutenberg.

На тестовом WP сравнены 13 секций и геометрия 176–182 текстовых / графических элементов с исходной сборкой при ширинах окна 390, 768 и 1440 px. В проверенном начальном состоянии расхождений не найдено. Это не заявление о полной попиксельной идентичности всех возможных состояний и тем WordPress.

## Обновление 0.6.0: изоляция от темы WordPress

Каждый импорт теперь создаёт один корневой блок `<div id="hop-gutenberg">`, внутри которого находятся все блоки лендинга. Базовый reset и стили лендинга привязаны к этому ID, поэтому типографика, отступы, изображения, формы и сетки меньше зависят от CSS активной темы. Для страниц, импортированных более ранней версией, плагин добавляет ID при выводе без изменения записи в базе.

Swiper поставляется локально внутри проверенного JS-бандла: внешняя CDN-библиотека не требуется. Инициализация карусели, элементы навигации, сравнение «до/после», квиз и модальные окна ограничены содержимым `#hop-gutenberg`.

## Обновление 0.6.1: типографика темы и Gutenberg

Заголовки h1–h6 без `.has-text-color` наследуют цвет секции внутри `#hop-gutenberg`. Сброшены регистр, тень, межбуквенный интервал и базовые параметры заголовков; исходные стили секций загружаются после reset и сохраняют оформление лендинга. Цвет, выбранный в Gutenberg из палитры или произвольным значением, сохраняется. Reset подключается для обоих профилей импорта, на сайте и в редакторе.

Плагин не удаляет `cs-inline-css` и другие стили X / Cornerstone. Глобальных сбросов `body` и `.wp-site-blocks` больше нет. Правила внешней обёртки действуют только для собственного шаблона `.lr-page-canvas`. Подключение фронтенд-стилей перенесено на приоритет 100.

Правило для новых страниц: используйте один корневой Group с anchor `hop-gutenberg`, нативные блоки с корректной сериализацией и общий CSS плагина. Новым служебным классам назначайте префикс `lr-ai-`; все правила ограничивайте `#hop-gutenberg`. Существующие классы точного профиля сохраняются, поскольку на них опираются исходные стили и интерактивы. Не добавляйте глобальные правила для темы и не отключайте её CSS. Для тёмной секции задавайте цвет контейнеру: заголовки без собственного цвета его унаследуют.

Вставка → Паттерны → **Ленремонт · Страницы** → **Страница услуги**. Корневая группа имеет класс `lr-ai-page` и ID `hop-gutenberg`. Внутри — редактируемые нативные блоки: первый экран, преимущества, услуги, цены, этапы, отзывы, FAQ и контакты. Заполните изображение и замените заглушки до публикации. Дополнительные секции доступны в **Ленремонт · Секции**, кнопки — в **Ленремонт · Элементы**. Вставляйте их внутрь корневой группы; при дублировании секций следите за уникальностью якорей.

Это обычные несинхронизированные паттерны. Тексты и фотографии меняются независимо, а общий CSS обновляет оформление всех страниц этой библиотеки. Файлы: `assets/design-system.css`, `patterns/design-system.php`, инструкция **`AGENT-GUIDE.md`**. Общий CSS загружается через `enqueue_block_assets` на сайте и внутри редактора; он ограничен `.lr-ai-page`, без новых скриптов. На страницах без этого класса правила не применяются и шрифт не используется.

Пять существующих лендингов сохраняют свой точный профиль. Его CSS дополнительно ограничен `.lr-reference`, чтобы не попадать на новые страницы в редакторе. Их JSON менять не нужно. Новую библиотеку можно использовать вместе с ними; массового преобразования существующих страниц нет.

Проверка 0.7.0 на локальном WordPress 7.1.1: зарегистрированы все 10 паттернов, 105 блоков демонстрационной страницы и каждый паттерн проходят проверку `wp.blocks.parse`, страница проходит повторный serialize/parse. CSS загружается в iframe Gutenberg в Chrome. На фронтенде при 1440 и 390 px нет горизонтального переполнения, сетки адаптируются, нативный FAQ раскрывается. В отдельном точном лендинге проверены цвет Hero и инициализация Swiper. Проверка с реальными стилями X / Cornerstone на production не выполнялась. Демо содержит заглушки и сохранено только черновиком.

## Исправление 0.7.1: стили ранее импортированных страниц в редакторе

Gutenberg назначает редактируемым блокам служебные DOM ID `block-…`; сохранённый anchor `hop-gutenberg` нельзя использовать как единственный селектор холста. В 0.6–0.7.0 это оставляло старые страницы без оформления в редакторе, хотя CSS-файлы загружались. Версия 0.7.1 добавляет отдельный `editor-content.css`, ограниченный `.editor-styles-wrapper` и корневыми классами `.lr-reference` / `.lr-imported-page`. Он генерируется из тех же исходных CSS командой `node wordpress-plugin/build-editor-styles.mjs` (также автоматически при экспорте профиля). Фронтенд по-прежнему изолирован через `#hop-gutenberg`. Содержимое страниц и их ID не изменяются, повторный импорт не нужен.

В реальном редакторе локального WP проверены старая главная (468 блоков), страница багги (418 блоков) и новая дизайн-система (105 блоков): оформление применяется, невалидных блоков нет, открытие страницы не создаёт несохранённых изменений.

## Текущие ограничения

- HTML-режим переносит семантическую структуру и контент, но не произвольные CSS и JavaScript.
- Точный профиль подготовлен для пяти страниц этого проекта. Для других исходников нужно подготовить соответствующий профиль / экспорт; базовый JSON v1 остаётся типовым. Это не универсальное точное преобразование любого сайта.
- Внешние изображения остаются внешними URL; перенос в медиатеку будет отдельным этапом.
- Изображения пяти примеров и шрифты включены в плагин. Маркер `{{pluginUrl}}` заменяется при импорте адресом установленного плагина.
- На основном сайте заявки обрабатывает существующий скрипт по data-атрибутам форм (по информации владельца сайта). Плагин сохраняет эти атрибуты; передачу персональных данных на локальных тестах не выполняли.
- Поле `slug` из JSON автоматически не применяется. SEO заполняется по правилам 0.8.0 выше. При переносе задайте адреса по каталогу до публикации. На тестовом сайте адреса и шаблон назначены отдельно ограниченным локальным скриптом `wordpress-plugin/ops/prepare-pages.php`; он не предназначен для запуска на production.
- ZIP-пакеты пока не поддерживаются.
