# Дизайн-система Ленремонт для Gutenberg

## Источник истины

- `assets/design-system.css`: общие токены и компоненты.
- `patterns/design-system.php`: корректно сериализованные нативные блоки.
- Три категории вставки: «Ленремонт · Страницы», «Ленремонт · Секции», «Ленремонт · Элементы».

Это начальная библиотека на основе текущего лендинга, а не утверждённый корпоративный брендбук. Используйте её для новых страниц. Пять точных переносов мототехники остаются на отдельном профиле `lr-reference`: не переименовывайте их классы автоматически.

## Сборка страницы

1. Вставьте паттерн `lenremont/ai-page` один раз. Он создаёт корневой Group с `className: "lr-ai-page"`, `anchor: "hop-gutenberg"`, `layout: { "type": "default" }`.
2. Все секции помещайте внутрь этого Group. Не вставляйте полную страницу внутрь другой страницы. ID `hop-gutenberg` должен встречаться один раз.
3. Отдельные паттерны вставляются **внутрь** корня. Это заготовки, а не синхронизированные паттерны: редактирование содержания одной вставки не меняет остальные.
4. Замените все тексты-заглушки, заполните блок изображения, добавьте осмысленный alt. Проверьте цены, гарантии, телефон, отзывы и ссылки. Не создавайте вымышленные отзывы, рейтинги, сроки, лицензии или преимущества.
5. Сохраните один H1. Заголовки секций — H2, заголовки карточек — H3. Проверьте якоря `lr-ai-contact` и `lr-ai-process`, особенно после дублирования секций.
6. Для программной сборки используйте `wp.blocks.createBlock` и `wp.blocks.serialize`; для повторного использования паттерна — `wp.blocks.parse(pattern.content)`. Перед сохранением проверьте `isValid` всех блоков и повторный parse/serialize. Не собирайте всю страницу в `core/html`.
7. Готовую сериализованную разметку можно вставить в режим Gutenberg-разметки существующей панели «Импорт страницы». JSON v2 `astro-main-v1` предназначен только для пяти точных переносов; не выдавайте произвольную новую страницу за этот профиль.
8. Slug и шаблон страницы задавайте отдельно. В JSON добавляйте индивидуальный объект `seo` с `title`, `description`, `breadcrumbsTitle`, `ogTitle`, `ogDescription`: импортёр 0.8.0 заполняет соответствующие поля `on_yoast_wpseo_*` сайта. Для уже готовой страницы используйте «Применить только SEO». Не указывайте canonical, URL крошек или ID картинки без явной необходимости; не меняйте индексацию. Плагин не публикует страницу автоматически. Сначала сохраните черновик и проверьте результат.

## Разрешённые классы

| Назначение | Класс |
| --- | --- |
| Корневая группа | `lr-ai-page` |
| Секция с адаптивными отступами | `lr-ai-section` |
| Ограничение ширины контента | `lr-ai-container` |
| Вертикальные интервалы между детьми | `lr-ai-stack` |
| Сетка 3 / 2 / 4 колонки | `lr-ai-grid`, дополнительно `lr-ai-grid--two` / `lr-ai-grid--four` |
| Тёмная / светло-серая секция | `lr-ai-dark` / `lr-ai-soft` |
| Карточка | `lr-ai-card lr-ai-stack` |
| Надзаголовок / вводный текст | `lr-ai-eyebrow` / `lr-ai-lead` |
| Приглушённый текст / акцент / подпись | `lr-ai-muted` / `lr-ai-accent` / `lr-ai-small` |
| Цена / изображение | `lr-ai-price` / `lr-ai-media` |
| Контейнер кнопок (core/buttons) | `lr-ai-buttons` |
| Кнопка (core/button) | `lr-ai-button`, дополнительно `lr-ai-button--outline` |
| Раскрывающийся вопрос (core/details) | `lr-ai-faq` |
| Отзыв (core/quote) | `lr-ai-review` |

Сетка становится одноколоночной до 700 px; четыре колонки переходят в две до 960 px. Классы ставьте на блоки, не на вручную добавленные обёртки внутри RichText.

## Правила оформления

- Все новые классы начинаются с `lr-ai-`. Все CSS-селекторы ограничены `.lr-ai-page`. Запрещены глобальные `body`, `h1`, `p`, `a` и сбросы темы.
- В CSS используется `:is(#hop-gutenberg.lr-ai-page, .lr-ai-page)`: класс остаётся обязательным, ID повышает специфичность относительно темы. Группа работает и при ручном назначении только класса.
- Цвета, шрифт, ширина, интервалы, радиусы и состояния компонентов находятся в одном CSS, а не копируются по страницам. Базовые значения → смысловые переменные → параметры компонентов.
- Локально редактируйте текст, картинки, ссылки, порядок, число карточек и доступные настройки цветов/отступов Gutenberg. На тёмной секции меняется набор смысловых переменных. Ручной цвет Gutenberg сохраняется; после смены фона проверьте контраст.
- Для варианта, повторяющегося на нескольких страницах, добавьте документированный класс в общий CSS. Не добавляйте десятки inline-стилей и `!important` ради обхода темы.
- В паттернах нет скрытых форм или собственного обработчика заявок. Используйте существующий проверенный блок/интеграцию сайта. Не имитируйте успешную отправку.
- Базовые компоненты не требуют Swiper или другого JavaScript. Если нужен новый интерактив, подключайте его отдельно и ограничивайте обработчики корнем страницы.
- Стили X / Cornerstone не удалять. Специфичность не даёт абсолютной защиты от внешнего `!important`; реальные конфликты проверять и исправлять точечно.

## Контроль перед передачей

Проверьте сериализацию блоков, отсутствие повторных ID и заглушек, корректность CTA, контраст, фокус клавиатуры и FAQ. Сравните редактор с фронтендом на 390 и 1440 px. Изменения общих CSS проверяйте также на ранее созданных страницах. Существующий контент не перезаписывайте без необходимости.
