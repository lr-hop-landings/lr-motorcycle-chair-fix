# Инструменты, тесты и обновление

## Переносимая рабочая копия

`scripts/lr-wp.mjs` находит свой комплект относительно `import.meta.url`, не текущего каталога. Указывайте абсолютные пути; пути с пробелами берите в кавычки. `init` копирует снимок в **новый** каталог, ничего не меняя в WordPress. Родитель выходного каталога должен существовать.

```text
node "<skill>/scripts/lr-wp.mjs" info
node "<skill>/scripts/lr-wp.mjs" init --out "<project>/lenremont-workbench"
node "<skill>/scripts/lr-wp.mjs" test --workspace "<project>/lenremont-workbench"
```

Базовые 8 тестов используют Node без npm-зависимостей. Сам CLI проверяется командой `node "<skill>/scripts/tool.test.mjs"` (создаёт временную копию комплекта, не обращается к WP). Для PostCSS и полного теста выполните **в рабочей копии** `npm ci --ignore-scripts`, затем:

```text
node "<skill>/scripts/lr-wp.mjs" build-editor --workspace "<project>/lenremont-workbench"
node "<skill>/scripts/lr-wp.mjs" test --workspace "<project>/lenremont-workbench" --full
node "<skill>/scripts/lr-wp.mjs" package --workspace "<project>/lenremont-workbench" --out "<project>/lenremont-page-importer.zip"
```

Для упаковки нужен Python 3 (или `--python <executable>`). ZIP создаётся с корневой папкой `lenremont-page-importer`, не перезаписывает существующий архив и не включает tests/legacy/toolchain. Скрипт не утверждает, что релиз прошёл тесты: выполните тесты перед упаковкой. PHP lint запускайте отдельно фактическим PHP целевого диапазона. PHPUnit в этом проекте не настроен.

Полный тест проверяет пять исходных манифестов, CSS scope и межстраничные ссылки. Моки не проверяют HTML-сериализацию реального Gutenberg. PHP-интеграционные тесты и browser-regression требуют отдельного тестового WordPress; сначала прочитайте их, поскольку часть fixtures создаёт/удаляет записи и часть ожидает конкретные ID. Не запускать всё `tests/*.php` циклом.

## Установка/обновление WP

Сначала только локально/на staging, если пользователь не запросил другой конкретный сайт. Уточните существующий путь/URL/запись, считайте версию и сравните файлы. Обновление плагина не требует удаления страниц или деинсталляции.

Для уже разрешённого обновления: резервная копия точной папки плагина и БД, сохранение несохранённых правок пользователя, проверенный ZIP, штатная замена плагина или ограниченное копирование только нужных файлов. Не копировать весь проект, не трогать uploads/themes/wp-config. Локальные изменения установленной версии сначала сравнить. При изменении списка файлов не оставлять старые исполняемые файлы молча; спланировать отдельное ограниченное удаление после backup.

Затем активация/статус, отсутствие PHP fatal, загрузка assets, старый лендинг, новая нейтральная страница, обычная страница темы, редактор save/reload. Проверить фактический URL, template, ссылки и SEO отдельно. Доставка форм — отдельная проверка по согласованию, не отправлять реальные персональные данные для smoke-теста. Не обещать «достаточно установить плагин» для произвольного сайта.

Исторический локальный сайт и ID из README — только происхождение, не цель по умолчанию. Production автоматически не обновлять. Нет команды `deploy` в этом инструменте: запись на сайт остаётся явным действием с проверкой контекста.

## Исторические экспортёры

В `assets/toolkit/legacy/` сохранены ops, export-reference, sync-quiz-data, update-seo-examples. У некоторых относительные пути уже не соответствуют расположению, зашиты пять маршрутов/ID, отсутствуют старые промежуточные входы. Это **исходный материал для адаптации, не поддерживаемые команды**.

Для нового экспортёра исходного Astro-профиля: задайте явные source/build/output/catalog/SEO paths; проверьте границы файлов, совпадение структуры секций и CSS/JS всех страниц. Собранные assets берите только из проверенного пользовательского проекта. Не запускайте импортированный JS как данные. `sync-quiz-data.mjs` использует vm и устаревшую структуру JSON — не запускать на современных v2-примерах. Готовые assets уже включены в комплект; экспорт не нужен для обычной сборки страницы.

## Обновление глобального скилла

Скилл содержит фиксированный снимок, не symlink на исходный проект. Рабочие изменения одного проекта не распространяются автоматически. Когда пользователь просит обновить общий комплект: сравнить версии/локальные правки, сохранить backup, перенести проверенные исходники/тесты/примеры и поддерживаемые tooling-поправки, обновить references и прогнать тесты из постороннего cwd. Не включать секреты, WP-конфиги, node_modules, архивы старых релизов и дампы БД. Не заменять новый глобальный снимок более старой копией из проекта.

Портируемые tooling-поправки к снимку 0.13.0: отдельный editor-overrides.css включён в builder; тест CSS допускает ID-селектор только при наличии эквивалентного class-only fallback в том же правиле. Runtime плагина при извлечении не изменялся.
