# Lenremont Gutenberg

Глобальный переносимый комплект для **Lenremont - Gutenberg Page Importer**. Язык общения по умолчанию — язык пользователя. Плагин в комплекте: **0.13.0**, WordPress ≥6.7, PHP ≥7.4. Node ≥22 нужен только для инструментов на машине агента, не на WP-хостинге.

## Начало работы из любого проекта

Пути ниже относительны каталогу этого SKILL.md, а не текущему проекту. Сначала выполните `node "<skill>/scripts/lr-wp.mjs" info`. Это чтение комплекта без обращения к сайту.

Для разработки или сборки создайте независимую рабочую копию:

```text
node "<skill>/scripts/lr-wp.mjs" init --out "<project>/lenremont-workbench"
```

Команда отказывается перезаписывать существующий каталог. В копии находятся плагин, примеры, тесты, сборщик CSS и исторические скрипты. Не редактируйте глобальный комплект при обычной сборке одной страницы. Если в проекте уже есть плагин, сначала сравните его версию и изменения; не заменяйте его снимком автоматически.

## Выбрать рабочий процесс

- **Собрать страницу, JSON, паттерны или перелинковку:** прочитайте [references/pages.md](references/pages.md). Для формата JSON также [references/manifest.md](references/manifest.md).
- **Изменить плагин, стили, квиз или библиотеку:** прочитайте [references/plugin.md](references/plugin.md); затем запускайте тесты из рабочей копии.
- **Проверить, упаковать, обновить WP или сам комплект:** прочитайте [references/operations.md](references/operations.md).
- **REST API / MCP / безбраузерный импорт:** сначала [references/integration-status.md](references/integration-status.md). Рабочего REST/MCP-импортера пока нет; предложение сохранено в [references/ide-import-spec.md](references/ide-import-spec.md). Не выдавайте планируемые эндпоинты за существующие.

## Инварианты

1. Один корневой Group с anchor `hop-gutenberg`. Не смешивать `lr-reference` и `lr-ai-page` в одном контейнере. DOM ID блока в редакторе — `block-…`, не сохранённый anchor.
2. Новые стандартные секции/паттерны нейтральны: текст-рыба, заглушки изображений, демонстрационный квиз. Оригинальные пять JSON по-прежнему содержат реальные мотолендинги. Не путать эти два источника.
3. Содержимое сохраняется как дерево Gutenberg-блоков, не один HTML-блок. Сериализация — реальным `wp.blocks`, затем сохранение и повторное открытие в редакторе. CLI проверяет структуру, но не заменяет проверку сериализации Gutenberg.
4. Исходные CSS-классы сохраняются; новые служебные классы имеют префикс. CSS не выходит за свой корень. Не отключать стили X/Cornerstone, не сбрасывать `body`, не добавлять вторую глобальную копию Swiper.
5. Новая заготовка не должна переписывать существующие страницы. Изменения общего CSS, в отличие от текста паттерна, могут затронуть все страницы этого профиля.
6. Сборка/проверка не является разрешением на публикацию или замену production. Перед записью установить точный сайт, запись и режим операции. По умолчанию предлагать черновик. Не использовать старые ID из примеров как целевые.
7. Формы на прежнем lenremont.ru обслуживает внешний обработчик по data-атрибутам (со слов владельца). На другом сайте его наличие не гарантировано. Не показывать ложный успех. Демоквиз 0.13.0 ничего не отправляет.
8. SEO работает с конкретными полями `on_yoast_wpseo_*` открытого редактора, а не с любым Yoast по умолчанию. Slug, шаблон, публикация, медиатека и редиректы требуют отдельных действий.

## Где находится всё остальное

`assets/toolkit/wordpress-plugin/lenremont-page-importer/` — полный снимок исходников, локальных медиа, примеров JSON, CSS/JS, блоков и документации плагина. `assets/toolkit/wordpress-plugin/tests/` — тесты. `assets/toolkit/legacy/` — исторические операции со старыми путями/ID; никогда не запускать без адаптации и проверки назначения. Встроенные README/AGENT-GUIDE содержат историю; актуальные правила 0.13.0 выше имеют приоритет над старыми инструкциями о библиотеке.

Точка входа инструмента: `scripts/lr-wp.mjs help`. Он не обращается к WP, не публикует страницы, не создаёт ключи и не регистрирует MCP-серверы.
